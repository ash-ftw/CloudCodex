# Security Policy

## Supported Versions

We release patches and security updates for the current active release.

| Version | Supported          |
| ------- | ------------------ |
| 1.x     | :white_check_mark: |
| < 1.0   | :x:                |

## Reporting a Vulnerability

The CloudCodeX team takes security seriously. If you discover a security vulnerability within CloudCodeX, please report it privately.

**Please do NOT disclose vulnerabilities through public GitHub issues.**

### How to Report

1. Send an email to **ashishjacob810@gmail.com** with the subject `[SECURITY] CloudCodeX Vulnerability Report`.
2. Include the following details in your report:
   - Type of vulnerability (e.g., sandbox escape, remote code execution, authentication bypass, SQL injection)
   - Step-by-step instructions or proof-of-concept (PoC) to reproduce the issue
   - Potential impact of the vulnerability
   - Affected files and components (client, server, docker sandbox, or worker)
   - Any suggested remediation or mitigations

### What to Expect

- **Acknowledgment:** We will acknowledge receipt of your vulnerability report within 48 hours.
- **Assessment:** We will validate and evaluate the severity and impact of the reported issue.
- **Resolution:** We will work on a patch and coordinate a public release date with you.
- **Credit:** Upon verification and resolution, we will gladly credit you in the release notes (if desired).
